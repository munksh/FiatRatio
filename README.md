# Fiat Ratio

Money for Sailfish OS, the Fiat way. Built on a personal finance database kept since 2022, made into an app when the Jolla Phone arrived. A budget month that starts when the salary arrives, or on the 1st. Recurring costs are planned ahead and confirmed when they happen. Savings, investments, a home and loans all add up to one net worth. Everything goes out to one open file, and comes back in from it. Costs you share can be entered at the full price, with only your part counted.

Part of the Fiat family. MIT licence.

## What's where

| Path | What |
|---|---|
| `src/store.*` | All data access. SQLite through QtSql, exposed to QML as `store`. Also the practice run, which lives in its own database file |
| `src/bundle.*` | Export and import of the bundle file (C++ port of `tools/fiat_bundle.py`) |
| `qml/data/schema.sql` | Database schema, version 2. Money is in minor units. Every row has a uuid |
| `qml/data/standard.json` | Standard buckets and categories with translations (generated by `tools/make_standard.py`) |
| `qml/FiatRatioTheme.qml` | Fiat or Ambience colours, `/apps/harbour-fiatratio/ambient` |
| `translations/` | `en`, `sv`, `de`, `ru` |
| `tools/` | The format reference, the icon, and the standard categories |

## The file format

`fiat-ratio-bundle`, version 2, is one JSON file:

```
{ "format": "fiat-ratio-bundle", "version": 2, "app_version": "...",
  "meta": { "base_currency": "SEK", "period_mode": "salary", ... },
  "tables": { "person": [...], "bucket": [...], "category": [...], "account": [...],
              "txn": [...], "valuation": [...], "schedule": [...], "period": [...], ... },
  "import_archive": [...] }
```

- Rows refer to each other by `uuid`.
- A foreign key column drops its `_id` (`category_id` becomes `"category": "<uuid>"`).
- Months are keyed by their label (`"2026-10"`).
- Amounts are integers in minor units, and they are *your part*. `amount_full`, `value_full` and `opening_full` hold the whole when something is shared.
- **Merge** keeps the newer `updated_at` for each row and carries tombstones (`deleted_at`). **Replace** empties the app and loads the file as it is.

`tools/fiat_bundle.py` is the specification by example. It reads and writes the same file, and also exports CSV and QIF (GnuCash, HomeBank). To bring bookkeeping in from somewhere else, write a small script that produces this file. That is how my Baserow history was moved in.

## Translations

The language follows the phone. Settings › Language overrides it on purpose, and the change takes effect at once. All four languages are kept by the author, who speaks them. Corrections are welcome as pull requests on `translations/*.ts`, and for the standard categories on `tools/make_standard.py`.

After changing strings in QML:

```
lupdate qml -ts translations/harbour-fiatratio-en.ts translations/harbour-fiatratio-sv.ts \
                translations/harbour-fiatratio-de.ts translations/harbour-fiatratio-ru.ts
python3 tools/fill_en_ts.py
```

`harbour-fiatratio-en.ts` must carry every string as its own translation. That is what lets an English override win over a phone set to Swedish.

To read everything through or correct it in a spreadsheet, `python3 tools/ts_sheet.py export translations.xlsx` writes all texts side by side, and `python3 tools/ts_sheet.py import translations.xlsx` reads the corrections back into the `.ts` files.

Standard category names live in `tools/make_standard.py`, not in the `.ts` files.

## Sailjail

`Permissions=Documents;Downloads` lets the app write exports to `~/Documents/fiat-ratio/` and read a bundle from Documents or Downloads. Check the names against `ls /etc/sailjail/permissions/` on the phone.
